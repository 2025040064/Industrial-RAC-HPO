# S3.0 报告：S2 等轮数消融的统计补全与口径核验

> 日期：2026-11-25
> 阶段：S3.0（补全 S2 实验的统计推断与口径核验）
> 性质：对 S2 正式消融（120 轮 = 4 组 × 3 种子 × 10 轮）的补全，**不重跑实验、不修改冻结基线**

---

## 1. 定位与边界（先声明，避免误读）

本报告是对 S2 已产出的 120 轮原始结果（`experiments/s2-ablation-b-20261125/results/ablation-results.json`）的**统计补全与口径核验**，不是新实验。

**三条不可逾越的边界**（贯穿全文）：

1. **等轮数 ≠ 等 CPU 预算**。S2 是等轮数（每组每种子 10 轮连续优化）实验，**不是**严格等 CPU 预算实验。等 CPU 预算的对照留待 S3.6。
2. **公开验证 ≠ 跨设备泛化 ≠ 隐藏集**。本报告所有统计结论的口径是**公开验证集 RMSE**（本地唯一可测口径）。
3. **RMSE 数值一致 ≠ Checkpoint 逐字节一致**。指标一致性与模型文件 SHA 一致性是两回事，必须分开核验。

## 4. 不确定性分析（95% 置信区间）

> 3 个配对种子 → df = 2，t 临界值 = 4.303（双尾）。**所有区间都很宽**，这是 n=3 的固有局限，必须如实报告，不得用点估计冒充确定结论。

| 效应 | 配对均值 | 95% CI | 区间宽度 | 是否跨零 |
|---|---|---|---|---|
| EMA@lr1e-5 | +3.43 | [−10.32, +17.18] | 27.50 | **跨零（不显著）** |
| EMA@lr3e-3 | +22.43 | [+16.30, +28.56] | 12.26 | 不跨零（显著有害） |
| lr@EMAoff | −25.18 | [−52.70, +2.34] | 55.04 | **跨零（不显著）** |
| lr@EMAon | −6.18 | [−18.80, +6.43] | 25.23 | **跨零（不显著）** |

### 4.1 诚实的统计结论（区别于 S2 点估计结论）

1. **唯一在 n=3 下统计显著的效应是「EMA 在 lr 下限 3e-3 下有害」**（+22.43，95%CI 不跨零，三个种子方向完全一致 +20/+25/+22）。这是 S2 结论里**最可靠**的一条。
2. **lr 下限的主效应方向一致（三个种子全为负）但 95%CI 跨零**——点估计 −15.68 是"有益"，但 n=3 下不足以在 5% 水平宣称显著。种子间方差（sd=7.96）远大于 EMA 效应的方差（sd=2.74），说明 lr 下限的收益对搜索种子更敏感。
3. **交互 +19.00 方向一致（三个种子全为正）但同样 95%CI 跨零**。交互的"稳定性"来自 EMA@lr3e-3 的强效应主导，不能独立声称交互显著。

> **修正 S2 正式报告的措辞**：S2 报告 §3 用"lr 主效应 −15.68（有益）、EMA 主效应 +12.93（有害）、交互 +19.00"的**点估计**表述，未附带置信区间。本报告补充：**这些点估计中，只有 EMA@lr3e-3 的 +22.43 在 n=3 下统计显著；lr 主效应与交互效应的点估计方向一致但置信区间跨零**，不能据此宣称"已证实"。

## 5. 口径核验（对应 S3.0 要求 5/6/7/8）

### 5.1 等轮数 ≠ 等 CPU 预算（要求 5）

S2 是**等轮数**实验（每组每种子 10 轮连续优化），各组训练内核（EMA on/off）的 CPU 成本**并不相同**：

| 组 | 训练内核 | 总 CPU(3 种子) |
|---|---|---|
| G0 | 直接 epoch-end | 5.8s |
| G1 | EMA（epoch 内 blend） | 1.9s |
| G2 | 直接 epoch-end | 1.9s |
| G3 | EMA | 2.0s |

- G0 的总 CPU 显著高于其他组，说明**各组并未消耗相同 CPU 预算**。
- **因此 S2 的任何"单位 CPU 收益"（RMSE↓/s）都不能作为跨组公平比较依据**，只能作为组内相对参考。S2 报告 §8 已就此加注，本报告再次强调：**不得将等轮数实验描述为等 CPU 预算实验**。
- 严格等 CPU 预算的对照（固定超参 / 随机搜索 / 标准 TPE / 原始 RAC / 改进 RAC）留待 **S3.6**，届时所有组共享同一预注册 CPU 预算。

### 5.2 平台 validation_metrics 与 old/new 的真实语义（要求 6）

**核验结论（修正 S2_PREAUDIT.md 的一处错误）**：

| 符号 | 代码来源 | 真实语义 |
|---|---|---|
| `old` | `contest_submission.py:230` `platform_metric(rnd.frame.get("current_validation"), metric)` | **平台在每轮开始注入的「当前父模型公开验证集指标」** |
| `new` | `contest_submission.py:330` `platform_metric(submission.get("summary"), metric)` | **平台对刚提交候选的「公开验证集指标」**（`submit_candidate` 的 `candidate_response` 返回） |
| `validation_metrics` | 平台 report `rounds[].validation_metrics` | **每轮公开验证集指标**（B 任务 round1 rmse=665.71，与本地复现完全一致） |
| 隐藏集指标 | 平台 report `report.metrics` | **最终评测一次**（B 任务 rmse=486.08），**只在最终 report 出现，不参与每轮 old/new** |

**关键修正**：S2_PREAUDIT.md 第 94 行曾写"平台主指标 old/new 来自隐藏集"，**这是错误表述**。经源码核验（`contest_submission.py:230/330` + SDK `round.py:submit_candidate` + 平台 report 逐轮字段）：

- **old/new 是公开验证集指标**（`validation_metrics`），**不是隐藏集**。
- 隐藏集指标只在最终 `report.metrics` 评测一次，**从不**作为每轮 old/new 参与接纳决策。
- 因此，v6 平台的逐轮接纳决策（`improved`）**完全由公开验证集驱动**，与本地 S2 消融的口径**一致**（都用公开验证 RMSE 判 improved）。

> 这一修正**不影响 S2 的结论**（S2 本就用公开验证口径），但**纠正了"平台用隐藏集驱动逐轮决策"的误解**，也澄清了 S3.1.5"本地 vs 平台搜索轨迹差异"的真实来源：**不是公开验证 vs 隐藏集驱动之差，而是（a）PyTRIO 决策服务通道（平台 RPC vs 本地直连 sampler）与（b）决策 prompt 的历史内容（平台含 platform_parent_metric=old，本地用 local_parent）之差**。

### 5.3 本地与平台 CPU 计量口径（要求 7）

**核验结论：不得将本地/平台 CPU 时间差异直接归因于"虚拟 CPU 配额"。**

| 项 | 本地 S2 | 平台 v6 B 任务 |
|---|---|---|
| 单轮训练 CPU | ~0.01s | 无逐轮拆解，但 10 轮合计 695.89s |
| 10 轮总 CPU | 1.9~5.8s | 695.89s（`cpu_accounting_status="measured"`） |
| 计量内容 | 仅 `time.process_time()`（本地续训+验证） | 平台实测，含容器调度、SDK RPC、隐藏集评测、模型推理（PyTRIO） |

- 相差 ~120~350 倍（695.89 / 1.9~5.8），**不是**此前 S2 报告 §8 写的 ~7000 倍（那是以"单轮 0.01s"为基准的口径混算；以 10 轮总 CPU 计，实际约 120~350 倍）。
- **真实原因**：平台 CPU 计量包含本地完全不涉及的环节（SDK RPC 往返、隐藏集评测服务、容器调度、PyTRIO 模型推理）。这些是**计量口径差异**，**没有任何证据指向"虚拟 CPU 配额"**。
- 平台 `cpu_accounting_status="measured"` 表明是实测值，但"实测"的含义是"平台侧计量的进程 CPU 总和"，其组成与本地 `process_time()` 的组成**不可直接对应**。
- **结论**：S3.6 做严格等预算实验时，必须**重新预注册一套本地 CPU 预算协议**，以本地统一的 `process_time()` 口径为锚，**不得**用平台 695.89s 直接折算成本地预算。

### 5.4 RMSE 数值一致 ≠ Checkpoint 逐字节一致（要求 8）

S2_PREAUDIT 的固定回放结论是"round1-3 RMSE diff=0.0000"，这证明的是**指标一致性**，**不是**模型文件逐字节一致：

| 核验对象 | 已核验 | 结论 |
|---|---|---|
| RMSE 数值一致 | round1-3 diff=0.0000，round4+ 浮点累积 +0.0166 | **指标一致**（前 3 轮精确） |
| Checkpoint SHA 逐字节一致 | 本地 `model_sha()`（权重+Adam state 排序后 hash） | **仅本地父/候选/选中链内自洽** |
| 平台 artifact SHA | 平台 report 只暴露 `artifact_id`，不含逐字节 SHA | **不可本地复现**（容器已销毁） |

- 本地回放的"RMSE 一致"只说明**续训机制（父检查点 + lr/bs/ep + EMA）忠实复现了平台公开验证指标**，**不能**据此断言"本地模型文件与平台 artifact 逐字节相同"。
- 平台的 `parent_sha256`/`candidate_sha256`/`selected_sha256` 的逐字节一致性，只能由平台 `selection-audit.jsonl`（已随容器销毁）证明，本地无法重建。
- **S3 后续任何"复现"表述，必须区分「指标一致性」（可本地证明）与「Checkpoint SHA 一致性」（仅平台可证明）两个层级。**

## 6. S3.0 结论汇总

1. **统计显著性**：n=3 下唯一显著的效应是 EMA@lr3e-3 有害（+22.43，95%CI[+16.30,+28.56]）。lr 主效应 −15.68 与交互 +19.00 方向一致但置信区间跨零，**不能宣称已证实**。
2. **口径**：S2 是等轮数实验，不是等 CPU 预算实验；等预算对照留 S3.6。
3. **平台语义修正**：old/new 是公开验证集指标，不是隐藏集；隐藏集只在最终 report.metrics 评测一次。
4. **CPU 口径**：本地/平台差异来自计量口径（SDK RPC/隐藏集评测/模型推理），无证据指向虚拟 CPU 配额。
5. **一致性分层**：RMSE 数值一致（指标层，可本地证明）≠ Checkpoint SHA 一致（字节层，仅平台可证明）。
6. **G2 的处置**（对应 S3.0 要求 2）：G2（EMA off + lr 3e-3）作为**训练侧待验证候选**，**不直接替代 v6**。其"公开验证最优"（628.40）与"小样本轴承泛化最差"（Bearing1_4 +109）的矛盾，正是 S3.3 鲁棒目标优化的动因。
